# NexusQuant

NexusQuant is a full-stack institutional-style AI scalping terminal focused on:

- NIFTY
- SENSEX

Stack:

- **Frontend**: React + Tailwind (Vite)
- **Backend**: FastAPI + asyncio + WebSocket
- **Broker/Data**: Upstox REST + MarketDataStreamerV3 flow
- **Infra**: Redis + PostgreSQL
- **Deploy**: Vercel (frontend), Render (backend)

---

## Critical Safety Rule

Trading and AI signal execution remain disabled until:

1. Upstox REST health check is successful
2. MarketDataStreamerV3 (or v3 authorized stream) is connected
3. Feed is fresh (stale-feed guard)

If any condition fails:

- broker status = disconnected
- signals/trading = disabled
- SAFE MODE = enabled automatically

No random/dummy market values are generated by the system.

## Backend architecture

Pipeline:

Upstox Feed  
→ Telemetry Layer  
→ Orderflow Engine  
→ Heatmap Engine  
→ AI Engine (TQS)  
→ Risk Engine  
→ Strategy Router  
→ Execution Router  
→ Trailing Engine  
→ Analytics + Journal

Core modules (in `backend/app/services`):

- `upstox_client.py`
- `orderflow_engine.py`
- `heatmap_engine.py`
- `ai_engine.py`
- `risk_engine.py`
- `strategy_router.py`
- `execution_router.py`
- `trailing_engine.py`
- `analytics_engine.py`
- `telemetry_hub.py`

Session intelligence supports:

- premarket analysis (Indian market)
- live market analysis
- closed market analysis mode

## Local run

### 1) Infra

```bash
docker compose up -d postgres redis
```

### 2) Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

### 3) Frontend

```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```

## API endpoints

- `GET /` service status
- `GET /api/health` broker + safe mode status
- `GET /api/telemetry/latest` latest telemetry frame
- `GET /api/analysis/session` pre/live/closed analysis payload
- `GET /api/analysis/closed-market` summarized closed-session analytics
- `GET /api/journal/trades` executed signal journal
- `WS /api/ws/telemetry` live telemetry stream for frontend

## Deployment

### Backend on Render

Use root `render.yaml`.

Set secrets in Render dashboard:

- `UPSTOX_ACCESS_TOKEN`
- `UPSTOX_CLIENT_ID`
- `UPSTOX_REDIRECT_URI`

Render provisions Redis + PostgreSQL and injects connection strings.

### Frontend on Vercel

Project root: `frontend`

Set env:

- `VITE_BACKEND_URL=https://<your-render-service>.onrender.com`

`frontend/vercel.json` is already configured for Vite output.

## Operational flow

1. Start in simulator mode
2. Validate in paper trading mode
3. Enable live trading only after execution quality and risk validation

This project enforces safe fallback behavior for stale feeds, high latency, broker disconnects, and execution failures.
